# Observability

ByPage separates operational visibility from optional product analytics. Neither path includes books, titles, notes, prompts, provider URLs, keys, account IDs, raw request URLs, HTTP headers, SQL or error stacks. Instrumentation uses a small explicit vocabulary in `src/lib/observability/schema.ts`; client properties are reconstructed from an allowlist both before storage and at ingestion.

## Local diagnostics

Open **Settings → Diagnostics & privacy** (`/me/diagnostics`). The page shows LCP, INP and CLS when the browser reports them, recent operations and errors, and a downloadable JSON report. A dash means a metric has not been reported, not a zero measurement. Development compilation and unsupported browser APIs can affect these values; compare production builds on representative devices.

The ring buffer holds at most 160 events in page memory. Five fixed slots retain the latest Web Vitals separately, so a long session does not lose its measurements when older operations leave the ring. Reloading clears both. They contain operation categories, bounded numeric durations/counts and route categories such as `reader`, never identifiers or text. Clearing diagnostics clears both measurements and the pending analytics queue, and aborts an outstanding analytics request where possible. Export is an explicit browser download, not an upload; report version 2 includes the latest `vitals` alongside recent `events`.

Library reads use one IndexedDB transaction with four requests, replacing the prior per-book note/position reads. Closely spaced focus, visibility and sync refreshes coalesce. EPUB parsing is loaded when import starts. The `library_load`, `book_import`, `book_open` and `reader_ready` durations help assess these paths; `reader_ready` currently measures stored data retrieval, not completed browser layout.

## Structured server logs

Logs go to stdout/stderr as JSON. Set `OBSERVABILITY_LOGS=0` to disable them. Example fields:

```json
{
  "timestamp": "2026-10-23T00:00:00.000Z",
  "service": "bypage",
  "level": "info",
  "event": "api.sync.read",
  "trace_id": "random-32-character-hex",
  "span_id": "random-16-character-hex",
  "outcome": "ok",
  "durationMs": 28,
  "status": 200
}
```

Instrumented APIs return `X-Request-Id`, matching the trace ID in their logs. IDs are generated by the server, not copied from arbitrary incoming headers. Errors are classified without recording exception messages or stacks. HTTP 4xx outcomes are errors for operation metrics but only 5xx and explicit failures should normally trigger availability alerts; use status filters in logs.

Route durations end when response headers are ready. `ai.completion` tracks the streaming proxy through completion, cancellation or failure. `ai.translation` covers a complete chunk request and validation. Background translation logs each acquired job attempt, backs off database outages to at most one retry a minute, and logs repeated scheduler failures at powers of two to limit noise.

Explicit `AbortError` cancellation is recorded as `cancelled` and does not set the span's error status. Translation time limits use `TimeoutError` and remain errors. A same-language change or pause retains prior checkpoints and does not increment provider-failure attempts; this cancellation path was statically reviewed, not exercised against a paid request in the source-language checks.

## Prometheus metrics

Set a random **server-only** `OBSERVABILITY_METRICS_TOKEN` of at least 24 characters. Without a valid bearer token, `/api/metrics` returns 404. Do not use an AI or account credential for this token.

```yaml
scrape_configs:
  - job_name: bypage
    metrics_path: /api/metrics
    scheme: https
    authorization:
      type: Bearer
      credentials_file: /run/secrets/bypage-metrics-token
    static_configs:
      - targets: ['your-deployment.example']
```

The normal Host/Origin proxy checks still apply. Scrape the configured host or send the canonical Host header when scraping privately. Scrape each replica individually; scraping only a load balancer mixes independent process counters.

- `bypage_operation_duration_seconds`: histogram labeled by fixed `operation` and `outcome`.
- `bypage_operations_active`: active operation gauge.
- `bypage_process_uptime_seconds`, `bypage_process_resident_memory_bytes`: process health.

Metrics are in memory and reset on restart. Suggested PromQL:

```promql
histogram_quantile(0.95, sum by (le, operation) (rate(bypage_operation_duration_seconds_bucket[5m])))
sum by (operation) (rate(bypage_operation_duration_seconds_count{outcome="error"}[5m]))
```

## OpenTelemetry traces

Set `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` to your OTLP HTTP/JSON collector endpoint (usually ending in `/v1/traces`). The project uses the standard HTTP exporter, not a vendor SDK. Leave the endpoint empty to disable export. Standard `OTEL_EXPORTER_OTLP_TRACES_HEADERS` supplies collector authentication if needed. `OTEL_SERVICE_NAME` defaults to `bypage`; `OTEL_TRACES_SAMPLE_RATIO` defaults to `0.1` and is clamped to 0–1.

Only explicit application spans use the private OpenTelemetry provider. Automatic HTTP, database and Next.js spans are intentionally not registered because they may contain private URLs, parameters or queries. Child spans use the application's asynchronous context. The bounded batch queue holds 512 spans and exports at most 64 at a time; collector failure must not block a reading operation. No collector or hosted account is bundled.

OpenTelemetry 3 requires Node.js 22.15 or newer. See the installed SDK types and [OpenTelemetry JavaScript instrumentation](https://opentelemetry.io/docs/languages/js/instrumentation/).

## Optional PostHog

Configure **both** server environment variables:

```dotenv
POSTHOG_PROJECT_TOKEN=your-project-token
POSTHOG_HOST=https://eu.i.posthog.com
```

Use the ingestion region for your project (EU, US, or a self-hosted HTTPS origin) and a **project token**, not a personal API key. The host must be an origin without credentials, path, query or fragment. Configuration is read at runtime; no analytics token is added to the browser bundle. Details: [PostHog capture API](https://posthog.com/docs/api/capture).

Configuration alone does not enable browser analytics. Each browser must explicitly opt in under **Diagnostics & privacy**. Consent is device-local and is not part of account sync or reading backups. DNT/GPC privacy signals override consent. Turning it off discards queued events and aborts any outstanding browser analytics request where possible; data that has reached the server cannot be recalled. This also applies when another tab revokes consent. Responses from an older consent session cannot overwrite the current delivery status.

The browser batches only events collected after opt-in and configuration availability. It sends at most 20 at a time to `/api/telemetry`, with one outstanding request per page. Keepalive fetches omit cookies and referrers, including when the page becomes hidden. The server validates the schema, limits bodies to 24 KiB, bounds per-process export concurrency and rate, and forwards to PostHog with `$process_person_profile: false` and `$geoip_disable: true`. No browser cookies, IP headers, user agent or referrer are forwarded. A random in-memory UUID identifies this page lifetime; it rotates on reload or re-enabling consent. This is not a stable user or account identifier. SPA route changes remain within the same page lifetime.

Events use the `bypage_` prefix. There is no autocapture, DOM capture, session replay, user identification, feature-flag fetch or browser PostHog SDK. Analytics failures are dropped without retrying or blocking reading. Rate limiting is per process; configure ingress limits for hostile traffic or large deployments.

## Validation boundaries

`npm run check:observability` runs six small, offline checks for schema privacy, bounded values, route categories, metrics authentication, log correlation and response preservation. `npm run typecheck` and `npm run build` check static compilation. Actual collector delivery, PostHog ingestion, account database behavior, real model latency and production Web Vitals require deployment-specific verification. Do not run paid model requests just to validate telemetry.
